# WordPress Hub — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: агентство/
фрилансер, управляющий несколькими сайтами на WordPress одновременно.

## 1. Credential type
URL + username + Application Password (WordPress-native, не сторонний OAuth) — самый
крупный по числу функций коннектор в портфеле, multi-site по природе с самого начала.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` С ЯВНЫМ АКЦЕНТОМ на мульти-сайт: "Подключите первый
   сайт — вы сможете добавить ещё столько, сколько нужно" (не одноразовый флоу, как у
   типовых single-account коннекторов) + ссылка "Users > Profile > Application
   Passwords" внутри самого WordPress.
2. **Форма** — site URL + username + Application Password (password-type), с явным
   объяснением разницы Application Password от обычного пароля пользователя (частая
   путаница — многие пробуют вставить обычный пароль).
3. **После первого сайта** — сразу видно "+ Добавить ещё сайт" как постоянный,
   заметный элемент — это НЕ разовое действие, а рутинная операция для агентства.
4. **После N сайтов** — `refresh_all_sites` сводка по всем сразу: кто офлайн, у кого
   истёк SSL, устаревшие плагины — единый дашборд-обзор портфеля сайтов, не список
   карточек без сводной аналитики.
5. **Bridge plugin awareness** — часть функций (SSH-независимые расширенные операции)
   требует установки Imperal Bridge плагина на сайте — идеально: явный индикатор
   "рекомендуем установить Bridge для полного функционала" на карточке сайта БЕЗ него,
   не молчаливое ограничение возможностей без объяснения.
6. **Ошибка "invalid application password"** — конкретное "проверьте, что это именно
   Application Password (Users > Profile), а не обычный пароль входа".
